Glossar

Die kanonische Sprache dieses Tracks. Jeder Begriff hier ist einer, den du schon verwendet hast oder gerade lernst. L1 = in Lektion 1 eingeführt.

Zugang & Identität

root L1
Der Administrator-Account mit unbegrenzten Rechten. Name auf jedem Linux-System identisch → Haupt-Angriffsziel. Man arbeitet nie direkt als root.
Avoid: „Admin", „Superuser-Login"
sudo-Benutzer L1
Ein normaler Account, der mit sudo einzelne Befehle kurzzeitig mit root-Rechten ausführt. Der Alltags-Account am Server.
Avoid: „Admin-User"
sudo L1
Befehlspräfix, das einen einzelnen Befehl mit root-Rechten ausführt (nach Passwort-Eingabe). „Rechte leihen statt besitzen."
Gruppe L1
Sammlung von Benutzern mit gemeinsamen Rechten. Mitgliedschaft in der Gruppe sudo erlaubt das Nutzen von sudo.

SSH & Schlüssel

SSH L1
Secure Shell — verschlüsselte Verbindung, um per Terminal auf einen entfernten Server zuzugreifen. Standard-Port 22.
SSH-Schlüsselpaar L1
Zwei zusammengehörige Dateien: der private Schlüssel (bleibt geheim auf deinem PC) und der öffentliche Schlüssel (liegt auf dem Server). Login gelingt nur, wenn beide zusammenpassen.
Avoid: „SSH-Passwort", „Zertifikat" (anderes Konzept)
authorized_keys L1
Datei ~/.ssh/authorized_keys eines Users; enthält die öffentlichen Schlüssel, die sich als dieser User einloggen dürfen. Braucht Rechte 600.
sshd_config L1
Konfigurationsdatei des SSH-Servers unter /etc/ssh/sshd_config. Hier wird Login-Verhalten gesteuert (root-Login, Passwort-Login …).
Avoid: „SSH-Settings" — Datei beim Namen nennen

System & Dateien

Datei-Rechte (700 / 600) L1
Dreistellige Oktalzahl für Besitzer/Gruppe/Andere. 700 = nur Besitzer darf lesen+schreiben+ausführen, sonst niemand. 600 = nur Besitzer lesen+schreiben. SSH verweigert Keys mit zu offenen Rechten.
systemctl L1
Steuerbefehl für systemd-Dienste: start, stop, restart, status, enable. (Ausführlich ab Lektion 6.)
