Was ist Effect? eine Idee

Ein Effect ist kein laufendes Programm — er ist eine Beschreibung davon. Und sein Typ verrät dir Erfolg, Fehler und Abhängigkeiten.

⏱ ~8 Min 🎯 Mission: verstehen, ob's sich lohnt 🧩 Du kennst: Promise, async/await, Generics

Das Problem, das du schon kennst

Du schreibst täglich sowas. Schau auf den Rückgabetyp:

async function getUser(id: string): Promise<User> {
  const res = await fetch(`/users/${id}`)
  if (!res.ok) throw new UserNotFound(id)   // ← verschwindet im Typ
  return res.json()
}
// Typ: Promise<User>

Der Typ Promise<User> sagt dir nur, was bei Erfolg rauskommt. Er verschweigt drei Dinge:

  • Was kann schiefgehen? Das throw ist im Typ unsichtbar. Du musst den Code lesen (oder es im Prod merken).
  • Was braucht die Funktion? Abhängigkeiten (HTTP-Client, DB, Config) sind nirgends sichtbar.
  • Wann läuft es? Schon beim Aufruf — sofort und unwiderruflich (eager).

Die eine Idee: Effect ist eine Beschreibung

Effect dreht das um. Du erzeugst zuerst eine Beschreibung dessen, was passieren soll — einen Plan. Der läuft nicht, bis du ihn explizit ausführst.

import { Effect } from "effect"

// Eine Beschreibung: "liefert 42, kann nicht fehlschlagen, braucht nichts"
const answer: Effect.Effect<number> = Effect.succeed(42)

// Bis hier ist NICHTS passiert. answer ist nur ein Plan.

// Erst hier läuft es:
const result = Effect.runSync(answer)   // 42
Mentales Modell

Rezept ≠ gekochtes Essen. Ein Effect ist das Rezept. runSync/runPromise ist das Kochen. Du kannst Rezepte herumreichen, kombinieren, anpassen — ganz ohne dass die Küche anspringt.

Offizielle Definition: „an immutable value that lazily describes a workflow or job.“ — Effect Docs, The Effect Type

Die drei Slots: Effect<A, E, R>

Das ist das Herzstück. Genau wie Promise<T> einen Typ-Slot hat, hat Effect drei:

Effect<User, NotFoundError, Database>
A · SuccessWas rauskommt, wenn alles klappt: ein User.
E · ErrorWomit es erwartet fehlschlagen kann: NotFoundError. Steht im Typ!
R · RequirementsWas es zum Laufen braucht: eine Database. Läuft nicht, bis die da ist.

Lies den Typ laut als einen Satz:

„Wenn ich das ausführe, bekomme ich einen User; es kann mit NotFoundError fehlschlagen; und es braucht eine Database, um zu laufen.“

Das ist der ganze Trick von Lektion 1. Wenn du einen Effect<A, E, R> in einen Satz übersetzen kannst, hast du das mentale Modell.

Kurz-Notiz: never

Lässt du E oder R weg, sind sie never. E = never → kann nicht (mit erwartetem Fehler) fehlschlagen. R = never → braucht nichts mehr, ist ausführbar. Deshalb war oben Effect<number> direkt mit runSync lauffähig.

Promise vs. Effect, nebeneinander

FragePromise<User>Effect<User, E, R>
Was kommt bei Erfolg raus?✅ User✅ User (Slot A)
Was kann schiefgehen?❌ unsichtbar (throw any)✅ im Typ (Slot E)
Was wird gebraucht?❌ nirgends✅ im Typ (Slot R)
Wann läuft es?sofort (eager)erst beim run… (lazy)

Sofortiges Feedback. Klick die Antwort an — kein Submit nötig.

1. In Effect<Order, PaymentError, Stripe> — was ist PaymentError?

✔ Genau. Mitte = E = erwarteter, behandelbarer Fehler. Im Typ sichtbar — anders als ein throw.
Nicht ganz. Reihenfolge ist <A, E, R> = Success, Error, Requirements. PaymentError steht in der Mitte → Fehler-Typ.

2. Du schreibst const e = Effect.succeed(1). Was passiert sofort?

✔ Richtig. Effects sind lazy. Erzeugen = Plan bauen. Laufen = explizit ausführen.
Das ist die Promise-Denke (eager). Ein Effect macht beim Erzeugen nichts — er beschreibt nur.

3. Was zeigt Effect<User, E, R>, das Promise<User> nicht zeigt?

✔ Sitzt. E + R sind der Mehrwert: Fehler und Dependencies werden Teil des Typs (und damit vom Compiler geprüft).
Den Erfolgs-Typ zeigen beide. Der Unterschied sind die zusätzlichen Slots E (Fehler) und R (Abhängigkeiten).

4. Eine Funktion gibt Effect<string, never, never> zurück. Was heißt das never an der mittleren Stelle?

✔ Korrekt. never in E = „solche Fehler gibt es nicht“. Und never in R = braucht nichts → direkt ausführbar.
never ist der „leere“ Typ: kein erwarteter Fehler möglich. (Nicht: immer Fehler, nicht: unbekannt.)

Dein Win

Du kannst jetzt jeden Effect<A, E, R> in einen deutschen Satz übersetzen — „liefert A, kann mit E fehlschlagen, braucht R“ — und weißt, dass er erst beim run… läuft. Das ist das Fundament; alles Weitere (Fehler behandeln, ausführen, komponieren, DI) hängt daran.
